# v1.6 → v1.6.1 마이그레이션

**문자(휴대폰) 인증 로그인은 프로젝트 설정 없이 늘 쓸 수 있다.** 서버가 가입 인증 설정의 `"SMS"` 값을 없앴다(aiapp-service#878).
SMS 로그인은 가입 절차 옵션이 아니라 로그인 수단이고, SNS 로그인처럼 설정 없이 제공된다.

## 무엇이 바뀌었나

| 위치 | 전 | 후 |
|---|---|---|
| `reference/sdk-surface.md` 문자 인증 로그인 절 | `fetchConfig()` 결과가 `"SMS"`일 때만 이 화면을 쓴다 | **기획에 휴대폰 로그인이 있으면** 쓴다. `fetchConfig()`로 분기하지 않는다 |
| `reference/sdk-surface.md` 가입 분기표 | `"SMS"` 행 | 행 제거 (`signup_verification`은 `NONE`·`EMAIL`) |
| 서버 거부 목록 | `403 문자 인증 로그인을 사용하지 않는 프로젝트` | 제거. 대신 `502 문자를 보내지 못했습니다`(바로 재시도 가능) |
| `features.json` `data_flow.account` | `signup_verification=SMS면 …` | `기획에 휴대폰 로그인이 있으면 …` |
| SDK `AuthConfig.signup_verification` 타입 | `"NONE" \| "EMAIL" \| "SMS" \| string` | `"NONE" \| "EMAIL" \| string` |

함께 적어 둔 주의사항이 있다.
- 아이디를 생략하고 가입한 회원은 `user.email`에 번호가 들어 있다. 이메일로 표시하지 않는다.
- 인증번호가 틀리면 `verify()` 결과가 `verified=false`로 온다. `error`만 보고 분기하지 않는다.

## 무엇이 바뀌지 않았나

- **SDK 동작은 바뀌지 않았다.** `useSmsLogin()`·`requestSmsLoginCode`·`loginWithSms`·`signupWithSms`는 그대로이고, 바뀐 것은 타입 주석뿐이다.

## 적용 절차

- **앱**: 조치할 것이 없다. v1.6.0 문서대로 `fetchConfig()`가 `"SMS"`인지 검사하는 앱은 그 분기에 영원히 들어가지 못한다. 그런 앱이 있다면 조건을 기획 기준으로 바꾼다. v1.6.0은 `next` 채널에만 배포됐으므로 해당하는 앱은 사실상 없다.
