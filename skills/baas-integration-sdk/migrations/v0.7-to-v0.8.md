# v0.7 → v0.8 마이그레이션

**결제위젯(인라인) 방식 추가 — `useStore().beginWidgetCheckout`.** 기존 `checkout()`(리다이렉트)은 그대로 두고 **선택지를 하나 늘린 것**이라 앱 조치가 없다(Tier 0).

> 이 노트는 사후 작성됐다. 당시 버전을 올릴 때 마이그레이션 문서를 남기지 않아 0.7→0.9 구간이 비어 있었고, 이력 보존을 위해 채웠다.

## 무엇이 바뀌었나

리다이렉트형 결제(`payment().requestPayment`)는 결제창으로 화면이 넘어가 **앱 뒤로가기가 사라지는** UX 문제가 있었다. 결제위젯 키(`gck_`) 프로젝트에서 앱 화면을 벗어나지 않는 인라인 결제를 제공한다.

- `core/toss.ts`: `TossWidgetsInstance` 타입(`widgets`/`setAmount`/`renderPaymentMethods`/`renderAgreement`/`requestPayment`)
- `core/store.ts`: `beginStoreWidgetCheckout` — prepare → 위젯 렌더 → `handle.requestPayment`
- `react/moreHooks.ts`: `useStore().beginWidgetCheckout` 노출

## 키 타입으로 분기했다 (이 버전 한정)

| 토스 키 | 결제 방식 |
|---|---|
| `ck_` (개별연동) | 기존 `checkout()` — 리다이렉트 |
| `gck_` (결제위젯) | 신규 `beginWidgetCheckout()` — 인라인 |

⚠️ **이 분기는 v0.9 에서 사라진다.** 0.9.0 이 리다이렉트 경로를 전면 제거하고 위젯 단일 방식으로 통일했다. 0.8 에서 `ck_` 키로 `checkout()` 을 쓰고 있었다면 0.9 로 올릴 때 조치가 필요하다 — `v0.8-to-v0.9.md` 참조.

## 앱 조치

없음. `checkout()` 을 쓰던 앱은 그대로 동작한다.

## 검증

빌드/테스트(27) 통과. buvamo(`gck_`) 실측 — 위젯이 앱 상세화면 안에 인라인 렌더(URL 유지·뒤로가기 유지) 확인.
