# v1.2 → v1.3 마이그레이션

**가입 절차가 프로젝트 설정으로 갈린다. 기존 앱은 무수정으로 계속 동작하지만, 이메일 인증을
켠 프로젝트에서는 가입 화면을 새로 구성해야 한다 — 화면별 판단이 필요하므로 Tier 2.**

## 무엇이 바뀌었나

### 서버 (aiapp-service)
프로젝트별로 가입 시 이메일 인증을 요구할 수 있게 됐다. **설정이 켜진 프로젝트에서 인증 없이
`signup()` 을 호출하면 서버가 401 로 거부한다** — 프론트 절차만이 아니라 서버 강제다.
설정을 켜지 않은 프로젝트(기본값)는 이전과 완전히 동일하게 동작한다.

가입 약관 전문도 공개 API 로 제공된다. 프로젝트 회원도 플랫폼에 저장되는 회원이라 통합 약관
동의가 필요한데, 생성 앱은 별도 약관 페이지로 이동할 수 없어 본문을 받아올 방법이 없었다.

### SDK 표면 (추가만 — 제거·의미 변경 없음)

| 항목 | 변경 |
|---|---|
| `getAuthConfig()` | 신규 — `{signup_verification, require_signup_approval}` |
| `getSignupTerms()` | 신규 — `{version, terms:{title,content}, privacy:{title,content}}` |
| `requestSignupEmailCode(email)` / `confirmSignupEmailCode(email, code)` | 신규 |
| `getSnsProviders()` | 신규 — 기존 전역 엔드포인트 래핑 (봉투를 벗겨 배열 반환) |
| `useSignup()` | 반환에 `config`/`terms`/`verified`/`fetchConfig`/`fetchTerms`/`sendCode`/`verifyCode` 추가. **`signup()` 시그니처는 불변** |
| `SignupOptions` | `terms_agreed`/`privacy_agreed`/`terms_version` 타입 명시(이전에도 전달은 가능했으나 자동완성이 안 됨) |

## 앱에서 무엇을 하면 되나

### 아무것도 안 해도 되는 경우
프로젝트가 이메일 인증을 켜지 않았다면 `signup_verification` 이 `"NONE"` 이라 이전과 동일하게
동작한다. **재빌드 불필요** — SDK 는 CDN 채널로 자동 반영된다.

### 이메일 인증을 켠 프로젝트 (교집합 파일만)

```tsx
const { config, verified, fetchConfig, sendCode, verifyCode, signup, error } = BaasSDK.useSignup();
useEffect(() => { fetchConfig(); }, []);

if (config?.signup_verification === "EMAIL") {
  // ① sendCode(email) → ② verifyCode(email, code) → ③ verified === true 일 때만 가입 버튼 활성화
}
await signup(email, pw, name, phone, { terms_agreed: true, privacy_agreed: true, terms_version });
```

지켜야 할 규칙:

1. **`fetchConfig()` 를 화면 진입마다 호출하고 그 결과로 분기한다.** 운영자가 콘솔에서 언제든
   토글하므로 생성 시점 값으로 고정하면 화면은 멀쩡한데 가입만 401 로 실패한다.
2. **`userId` 는 인증한 이메일과 같아야 한다.** 서버가 "인증한 이메일 == 가입 계정"을 대조한다.
3. 인증을 켠 프로젝트는 **아이디가 이메일 형식**이어야 한다(서버 400).
4. 재발송은 **60초 쿨다운**(429). `error.message` 를 노출하고 버튼을 그동안 비활성화한다.
5. 인증 코드는 가입 성공 시 소비된다 — 같은 코드로 두 번 가입할 수 없다.

### 약관 (모든 프로젝트 권장)

`fetchTerms()` 로 전문을 받아 가입 화면 안에서 접었다 펴는 형태로 노출하고, 두 항목 모두 필수
체크로 만든다. 동의 시 `terms_version` 을 그대로 `signup()` 에 넘기면 서버가 회원 기록에 남긴다
(약관 개정 시 재동의 대상 특정용). `content` 는 줄바꿈 포함 일반 텍스트라 `white-space: pre-wrap`
으로 렌더한다.

> 현재 서버는 약관 동의를 강제하지 않는다(기존 앱 호환). 그러나 **신규 가입 화면은 반드시
> 체크박스를 구성한다** — 추후 강제로 전환될 때 그대로 통과한다.

### SNS 가입

`getSnsProviders()` 결과로 버튼을 렌더한다. **`login_url` 은 fetch 대상이 아니라 페이지 이동
경로다**(`window.location.href`). 목록은 전역이므로 기획에서 특정 provider 만 쓰기로 했다면
결과를 필터해 렌더한다. **SNS 가입은 이메일 인증 대상이 아니다** — provider 가 이미 이메일을
검증했으므로 `signup_verification === "EMAIL"` 이어도 SNS 버튼은 그대로 노출한다.

## 검증

- 인증 미설정 프로젝트: 기존 가입 화면이 그대로 동작하는지
- 인증 설정 프로젝트: 코드 없이 가입 시도 시 401 이 뜨고 안내가 보이는지, 코드 확인 후 가입되는지
- 재발송 버튼을 연타했을 때 429 안내가 뜨는지
- 약관 체크 전에 가입 버튼이 비활성인지
- SNS 버튼이 페이지 이동으로 동작하는지(fetch 로 만들면 아무 일도 일어나지 않는다)
