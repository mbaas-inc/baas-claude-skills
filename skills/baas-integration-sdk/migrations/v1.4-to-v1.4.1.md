# v1.4.0 → v1.4.1 마이그레이션

**앱 조치 없음(Tier 0)** — SDK 표면은 한 글자도 바뀌지 않았다(`sdk/` 미변경, CDN 채널 무영향).
바뀐 것은 **생성 지침** 하나다. 이미 만들어진 앱은 그대로 동작한다.

`changed_features` 에 `board`·`notice` 를 적은 것은 그 기능을 **잘못 쓰는 방식**을 금지했기 때문이다.
기능의 계약이 바뀐 것은 아니다.

## 무엇이 추가됐나

`SKILL.md` 에 절 하나 — **"데이터 저장 — 고정 기능을 범용 저장소로 전용하지 않는다"**.

고정 기능의 스키마에 맞지 않는 데이터를 그 기능에 억지로 담는 것을 금지한다:

- 구조화 값(품종·생년월일·수량·상태 등)을 게시글 `content` 문자열에 인코딩하는 것
- `categories` 를 자유 입력 값 저장소로 쓰는 것 (정의값의 부분집합만 허용되는 닫힌 enum)

매핑되지 않는 데이터는 담을 프리미티브가 표면에 있는지 확인하고, 없으면 **미지원으로 보고**한다.

## 왜 필요했나 — 실측

native 라인(동적 컬렉션 미지원) 하네스 E2E 에서 드러났다. 커스텀 구조화 데이터 요구
(반려동물 프로필 — 이름·품종·생년월일·중성화 여부·메모)를 받은 에이전트가 미지원으로 보고하지
않고 **FREE 게시판을 범용 저장소로 전용**해 품종·생년월일을 `content` 에 인코딩하는 계획을 냈다.

에이전트 잘못이 아니었다 — `fallback` 은 "표면에 없는 기능" 만 막고 `board` 는 표면에 있는데,
게시판을 저장소로 돌려쓰지 말라는 규칙이 없었다. 현행 규칙상 정당한 판단이었다.

그 결과물이 미지원 보고보다 나쁘다. 에이전트가 스스로 나열한 열화:

- 문자열 인코딩이므로 **서버 검증·정렬·범위 질의 불가**(예: 생일 임박 순 정렬)
- `categories` 가 닫힌 enum 이라 자유 입력 품종·날짜를 담을 수 없다
- 목록 응답에 작성자 식별자가 없어(`author_id` 는 `fetchPost` 상세에만) **소유권 판정이 깨진다**
  — "내 반려동물" 목록도, 목록의 수정·삭제 버튼도 만들 수 없다

즉 **화면은 그려지는데 기능만 틀린 산출물**이 나온다.

## 라인별 결론이 다르다

같은 금지 규칙이지만 그다음이 갈린다.

| 라인 | 매핑되지 않는 데이터를 만나면 |
|---|---|
| `baas-integration-sdk` (동적 컬렉션 포함) | 동적 컬렉션으로 설계한다 |
| `baas-integration-sdk-native` | 담을 프리미티브가 없다 → **미지원으로 보고** |

native 판은 정본에서 파생 생성되므로(`scripts/build-native-skill.mjs`) 컬렉션을 가리키는 문장만
빠지고 금지 규칙과 그 근거는 그대로 남는다.

## 기존 앱에 이미 이런 구조가 있으면

**손대지 않아도 된다.** 이 규칙은 앞으로의 생성 지침이고, 동작하는 앱을 바꾸라는 뜻이 아니다.
다만 그 앱에서 "내 것만 보기"나 목록의 소유자 액션이 요구로 올라오면 그때는 구조를 바꿔야 한다 —
목록 응답에 작성자 식별자가 없다는 제약은 우회할 수 없다.
