# v1.5.0 → v1.5.1 마이그레이션

**문의하기(`inquiry`) 기능 신설** — 비로그인 Contact us/상담신청 폼이 SDK 표면에 first-class 로 추가됐다(SDK 1.5.0).
**순수 추가(additive)** 라 기존 배포 앱은 무영향(아래 Tier 0).

> v1.5(컬렉션 접근 정책 어휘 제거, `v1.4.1-to-v1.5.md`)와 이 노트는 **서로 독립**이다. 둘 다 Tier 0 이고 다른 기능 그룹을 다루므로
> 어느 쪽이 먼저 적용돼도 결과가 같다(main 에는 이 노트가 v1.5 노트보다 먼저 들어갈 수 있다).

## 무엇이 바뀌었나
- **신규 훅 `BaasSDK.useInquiry()`** → `{ config, fetchConfig, submit, loading, error }` + 코어 `BaasSDK.getInquiryConfig()` / `BaasSDK.submitInquiry(input)`.
  - `GET /public/inquiry/{project_id}/config` → `{ enabled, disabled_message, complete_message, consent_version, consent_label, consent_body }`.
  - `POST /public/inquiry/{project_id}` ← `{ name, contact?, email?, content, consent_agreed, consent_version }` → `{ accepted, message }`
    (항상 200 · 5분 내 같은 내용+연락처 재전송은 `"이미 접수되었습니다"` 로 성공 응답, 저장 없음).
  - `contact` 는 SDK 가 `normalizePhone` 으로 정규화하고, 빈 `contact`/`email` 은 전송에서 생략한다.
- **표면 문서**: `reference/sdk-surface.md` "문의하기 (inquiry)" 절 추가, 반환값-vs-state 표에 `useInquiry` 행 추가, 에러코드 표에 `BAD_REQUEST` 추가.
- **생성 지침 변경**: "문의/상담신청" 요청은 이제 `recipient`(발송대상) 가 아니라 `inquiry` 로 라우팅한다.
  `features.json` 의 `recipient` 키워드에서 `문의`·`상담신청` 을 빼고 `inquiry` 그룹에 실었다. 뉴스레터·구독·연락처 수집은 그대로 `recipient`.
- `recipient` 의 SDK 표면(`useRecipient().register`)·서버 동작 변화 **없음**. 그 외 기능 표면 변화 없음.

## 영향 / Tier (판정: features_used ∋ `inquiry`)
- **Tier 0 (전 기존 앱)**: `inquiry` 는 신규 그룹이라 기존 `baas-manifest.json` 의 `features_used` 에 들어있지 않다
  → 교집합이 항상 비어 **갱신 대상 아님**. 별도 조치 불필요.
- 새 앱에서 문의/상담신청 폼이 필요하면 `useInquiry` 를 사용한다(`sync-manifest.mjs` 가 `features_used` 에 `inquiry` 를 도출).

## 적용 절차
- 기존 앱: 없음(추가 기능).
- 신규 앱: 진입 시 `fetchConfig()` → `enabled` 분기 → 폼(이름·연락처 또는 이메일·내용·동의) → `submit({ …, consent_version: config.consent_version })` → `result.message` 안내 + 폼 초기화.
- (선택) 기존 앱이 발송대상(`useRecipient().register`)으로 문의를 받고 있다면: 그 동작은 그대로 유효하다. 소유자가 "문의 접수함·동의 문구 관리·접수 중단" 을 원할 때만 해당 폼을 `useInquiry` 로 바꾼다 — 사용자 요청에 따른 국소 UI 변경이지 이번 버전이 강제하는 갱신이 아니다.

## 전제(운영)
- 서버(aiapp-service)의 inquiry 라우트가 해당 SDK 채널이 쓰이는 환경에 배포되어 있어야 한다(alembic `a7f3c92d5b18` + 동의 문구 시드 `docs/sql/inquiry_consent_notice_1.0.sql`). 미배포 환경에서는 `fetchConfig` 가 404 → `error.message` 로 드러난다.
