# v1.1 → v1.2 마이그레이션

**공지/FAQ에 카테고리(분류 그룹)가 열렸다. 기존 앱은 무수정으로 계속 동작하지만, 카테고리를
등록한 프로젝트에서는 필터 UI를 붙이는 게 자연스럽다 — 화면별 판단이 필요하므로 Tier 2.**

## 무엇이 바뀌었나

### 서버 (aiapp-service)
공지사항·FAQ 게시판도 카테고리를 지원한다. 이전에는 동적 게시판(FREE/REVIEW/URL_LINK) 전용이었고
공지/FAQ는 저장 자체가 400으로 거부됐다. **프로젝트 관리자가 게시판 설정에서 분류 그룹을 등록한
경우에만** 값이 채워지고, 등록하지 않았으면 이전과 똑같이 `null`이다.

### SDK 표면 (추가만 — 제거·의미 변경 없음)

| 항목 | 변경 |
|---|---|
| `PostListOptions` | `category?`, `category_group?` 추가 (`useNotice`/`useFaq`/`useBoard`의 `fetchPosts`가 공유) |
| `PostListResult` | `board_settings?: BoardSettings \| null` **명시 타입화** (이전에도 런타임엔 있었으나 인덱스 시그니처라 자동완성이 안 됨) |
| `BoardPost` | `categories?: PostCategories \| null` 명시 타입화 |
| `PostCreateInput` | `categories?: PostCategories \| null` 명시 타입화 |
| 신규 타입 | `CategoryGroup { name, values }`, `PostCategories = Record<string, string[]>`, `BoardSettings` |

### ⚠️ transport 경로 변경 (Tier 0 — 앱 코드 무영향)

`listNoticePosts`/`listFaqPosts`가 **레거시 → 통합 엔드포인트**로 전환됐다.

```
이전: GET /public/boards/{notice|faq}/{pid}/posts     ← category 파라미터를 받지 않음
이후: GET /public/boards/{pid}/{NOTICE|FAQ}/posts     ← category, category_group 지원
```

상세도 `getNoticePost`/`getFaqPost`가 board_type 무관 공용 경로(`/public/boards/posts/{id}`)를 쓴다.
**호출부 시그니처는 그대로**라 앱 코드는 바뀌지 않는다. 전환한 이유: 레거시 경로에 필터
파라미터를 붙이면 서버가 조용히 무시해 "필터를 걸었는데 전체가 나오는" 무증상 실패가 된다.

## 앱에서 무엇을 하면 되나

### 아무것도 안 해도 되는 경우
프로젝트 관리자가 분류 그룹을 등록하지 않았다면 `board_settings.categories`가 `null`이라
이전과 동일하게 동작한다. **재빌드도 불필요** — SDK는 CDN 채널로 자동 반영된다.

### 필터 UI를 붙이는 경우 (교집합 파일만)

분류는 2단계다 — 게시판이 그룹을 정의하고, 게시글이 그중에서 선택한다.

```ts
posts.board_settings.categories  // [{ name: "카테고리", values: ["결제", "계정"] }] | null
posts.items[0].categories        // { "카테고리": ["결제"] } | null
```

지켜야 할 규칙:

1. **`board_settings.categories`가 있을 때만 필터 UI를 렌더한다.** 값을 하드코딩하지 말 것 —
   프로젝트마다 다르고 관리자가 언제든 바꾼다.
2. **그룹 이름이 `"카테고리"`(기본값)면 표시에서 접두사를 생략한다** (`결제`). 축이 둘 이상일
   때만 `유형: 결제`처럼 그룹명을 붙인다. 백오피스 표시 규칙과 맞춘 것이다.
3. 글 수가 적으면 전체를 받아 클라이언트에서 걸러도 된다. 목록이 길면(페이지네이션이 있으면)
   `fetchPosts({ category, category_group })`로 서버 필터를 쓴다 — 클라 필터는 현재 페이지만
   걸러지기 때문이다.
4. `category_group`을 함께 주면 그 그룹 안에서만 매칭한다. 축이 하나뿐이면 생략해도 된다.

```tsx
const { posts, fetchPosts } = BaasSDK.useFaq();
const [sel, setSel] = useState<{ group: string; value: string } | null>(null);

const groups = posts?.board_settings?.categories ?? [];
if (groups.length === 0) return <FaqList items={posts?.items ?? []} />;  // 분류 미등록 프로젝트

// 클라이언트 필터 (글 수가 적을 때)
const visible = sel
  ? posts.items.filter(p => p.categories?.[sel.group]?.includes(sel.value))
  : posts.items;
```

### 쓰기(동적 게시판)
`submitPost`/`editPost`의 `categories`는 `{ 그룹명: [값] }` 형태이며 **`board_settings.categories`의
부분집합**이어야 한다. 벗어나면 서버가 400으로 거부한다(그룹명 오타·허용 밖 값 모두).

## 검증

- 분류 미등록 프로젝트: 기존 화면이 그대로 동작하고 필터 UI가 렌더되지 않는지
- 분류 등록 프로젝트: 필터 칩이 `board_settings.categories`대로 나오고, 선택 시 목록이 좁혀지는지
- 서버 필터를 쓴다면 페이지네이션과 함께 동작하는지(1페이지만 걸러지지 않는지)
