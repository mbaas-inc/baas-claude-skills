# v0.12.1 → v0.13 마이그레이션

**훅 반환값 통일 — `useStore().fetchProducts` / `useSurvey().fetchSurveys` 가 이제 state 와 같은 배열을
반환한다**(이전엔 `{ items }` 봉투). 런타임 변경이므로 `next` 채널 재배포가 따른다.

## 불변식

> **훅에 state 가 있으면 `fetch*` 반환값 === 그 state 값.**

이전에 이 불변식을 어긴 함수는 딱 둘이었다 — `fetchProducts` 와 `fetchSurveys`. 둘 다 state 에는
배열을 넣으면서 반환은 봉투를 줬다. 다른 조회 훅(`useBoard`·`useNotice`·`useFaq`·`useComments`·
`useCollection`·`useReservation().fetchTargets`)은 원래부터 state 와 반환이 같았다.

## 왜 고쳤나 (실측)

연속 세대의 생성 앱에서 같은 크래시가 반복됐다:

```tsx
const res = await fetchProducts({});
setProducts(res ?? []);      // res 는 { items: [...] } 봉투
products.map(...)            // ❌ TypeError: x.map is not a function  (배포본에서만 드러남)
```

`tsc`·`eslint`·`build` 는 전부 통과한다 — `window.BaasSDK` 가 타입 없는 CDN 전역이라 모든 필드
접근이 `any` 이기 때문이다. 한 세대는 반대 방향(반환값 캡처)으로, 다른 세대는 state 사용으로
서로 다르게 우회했고, "둘 중 뭘 써야 하나"가 매번 재발했다. 규약 자체를 없애는 쪽으로 고쳤다.

## 앱 조치 (Tier 2 — 반환값을 쓰던 코드만)

**state 를 쓰던 코드는 조치 불필요.** 반환값을 쓰던 코드에서 `.items` 를 떼면 된다:

```tsx
// before
const res = await fetchProducts({ category_id });
setLocal(res?.items ?? []);
const surveys = (await fetchSurveys({ status: "OPEN" }))?.items ?? [];

// after
const items = await fetchProducts({ category_id });   // 이미 배열
setLocal(items ?? []);                                 // 실패 시 null (훅 실패 규약)
const surveys = (await fetchSurveys({ status: "OPEN" })) ?? [];
```

⚠️ 훅 액션은 실패 시 **throw 가 아니라 `null`** 을 반환한다(전역 규약) — `?? []` 가드는 그대로 필요하다.

## 영향 없는 것

- `products` / `surveys` **state 자체는 변화 없음**(원래 배열).
- 다른 훅의 반환·state, 엔드포인트, 결제 흐름, 접근 정책 — 전부 그대로.
- `fetchSlots`·`fetchTarget`·`fetchProduct`·`myOrders`·`myBookings` 는 **state 가 없는 passthrough** 라
  이전과 동일하게 백엔드 응답을 그대로 준다(변경 없음).
