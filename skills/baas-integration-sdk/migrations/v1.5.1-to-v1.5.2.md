# v1.5.1 → v1.5.2 마이그레이션

**문의 설정을 바꿀 수 있게 됐다** — 서버에 소유자 설정 API(aiapp-service#745), CLI 에 조회·변경 명령(baas-cli#22).
스킬은 그 사실만 반영한다. **SDK 표면·앱 코드 변화 0**(Tier 0).

## 무엇이 바뀌었나

문서 두 곳의 **거짓이 된 문장**을 고쳤다.

| 위치 | 전 | 후 |
|---|---|---|
| `reference/sdk-surface.md` 문의하기 절 | "앱이 설정을 바꾸는 API 는 없다(백오피스 소관) — 준비 작업 0." | 앱(SDK)이 못 바꾸는 것은 그대로. **준비 작업이 생겼다** — 알림이 어디로 가는지 확인해 사용자에게 알리고, 바꾸겠다고 할 때만 바꾼다 |
| `features.json` `data_flow.inquiry` | "앱이 설정하는 API 없음, 준비 작업 0" | 위와 같은 취지로 교체 |

핵심은 하나다 — **접수 알림은 소유자가 따로 정하지 않으면 가입 계정 이메일로 간다.**
설정을 조회하면 지금 주소와 함께 그것이 직접 정한 값인지(`configured` · `notify_email_source`)가
내려오므로, "지금은 가입하신 계정 이메일로 갑니다, 바꾸시겠어요"를 정확히 물을 수 있다.

## 무엇이 바뀌지 않았나

- **SDK 표면 무변화** — `useInquiry()`·`getInquiryConfig()`·`submitInquiry()` 그대로. 방문자용 공개 API 만 쓴다.
- **앱이 설정을 바꾸는 SDK API 는 여전히 없다.** 알림 주소는 사장님 연락처라 방문자 번들이 닿는 표면에 올리지 않는다.
- **CLI 명령·플래그 문법은 이 스킬에 적지 않는다.** v0.12 에서 정리한 스킬 ↔ CLI 경계(`v0.11-to-v0.12.md` ②)를
  그대로 지킨다 — 버전 라인이 독립이라 문법을 박아 두면 조용히 낡는다. 실행 문법은 `baas <group> <action> --help`.

## 왜 (지금 고치지 않으면)

에이전트가 "설정은 백오피스 소관"으로 읽고 문의 폼만 놓은 뒤 끝낸다. 그러면 알림은 소유자의 가입 계정
이메일로 조용히 나가고, **사장님은 문의가 어디로 오는지도 바꿀 수 있다는 것도 모른 채 남는다.**
콘솔 화면이 없는 것이 전제라 에이전트가 알려주지 않으면 알 방법이 없다.

## 적용 절차

- **앱**: 조치 없음. 런타임 SDK·매니페스트 `features_used` 변화 없고 재생성·재빌드 0.
- **새로 만드는 앱**: 문의 폼을 넣을 때 알림 주소 안내가 자동으로 따라온다.
- **이미 배포된 앱**: 갱신 대상이 아니다. 다만 문의 폼이 있는 프로젝트라면 알림 주소를 한 번 확인해
  사장님에게 알려 주는 편이 좋다 — 코드 문제가 아니라 **안내가 빠져 있던 문제**라 재생성으로는 해결되지 않는다.
