# v1.5.2 → v1.6 마이그레이션

**문자(휴대폰) 인증 로그인이 생겼다.** 서버에 프로젝트 가입 인증 설정 `SMS`와 문자 인증 로그인 API가 생겼다(aiapp-service#867). SDK는 그 API를 감싸 `useSmsLogin()`을 더한다.

## 무엇이 바뀌었나

### 서버
- **설정 값 추가**: 가입 인증 설정 `signup_verification`에 `"SMS"`가 생겼다. 이 값으로 켠 프로젝트에만 문자가 나간다.
- **인증번호 발송**: 가입 여부와 관계없이 보낸다.
- **인증번호 확인**: 가입된 번호면 그 자리에서 로그인(쿠키)시킨다. 처음 오는 번호면 `registered:false`로 알려 준다.
- **가입**: 처음 오는 번호는 통합 가입(SMS 방식)으로 가입하고, 가입과 동시에 로그인된다. 아이디와 비밀번호는 생략할 수 있다.

### SDK 표면 (추가만)

| 표면 | 변경 |
|---|---|
| `useSmsLogin()` | 신규. `{ step, phone, remainingAttempts, sendCode, verify, signup, reset, loading, error }` |
| `requestSmsLoginCode(phone)` | 신규. `POST /account/sms-login/request` |
| `loginWithSms(phone, code)` | 신규. `POST /account/sms-login` → `{ verified, registered, remaining_attempts }` |
| `signupWithSms({ phone, name, termsAgreed, privacyAgreed, userId?, userPw? })` | 신규. `POST /account/signup/unified` (identifier_type=SMS) |
| `AuthConfig.signup_verification` | 타입에 `"SMS"` 추가 |

기존 `useLogin`·`useSignup`·`signup()`은 바뀌지 않았다.

## 앱에서 무엇을 하면 되나

`fetchConfig()` 결과가 `"SMS"`인 프로젝트만 대상이다. `"NONE"`·`"EMAIL"`인 앱은 **조치할 것이 없다.**

```tsx
const { config, fetchConfig } = BaasSDK.useSignup();
useEffect(() => { fetchConfig(); }, []);

if (config?.signup_verification === "SMS") {
  // 로그인·가입 화면을 useSmsLogin() 한 화면으로 바꾼다 — reference/sdk-surface.md 「문자 인증 로그인」
}
```

- **로그인 화면과 가입 화면을 하나로 합친다.** 사용자는 자기가 가입했는지 모르고 번호부터 넣는다.
- **`step`으로 렌더한다.**
  - `"phone"`: 번호 입력
  - `"code"`: 인증번호 입력
  - `"signup"`: 이름·약관 입력
  - `"done"`: 로그인 완료
  - `"pending"`: 승인 대기
- **약관은 `"signup"` 단계 안에서 받는다.** 전문은 `fetchTerms()`로 가져온다.

## 왜 (지금 고치지 않으면)

설정을 `"SMS"`로 바꾼 프로젝트는 서버가 인증 없는 `signup()`을 401로 거부한다. 기존 이메일·비밀번호 가입 화면은 겉으로는 멀쩡해 보이지만 가입만 실패한다.

## 적용 절차

- **SMS를 쓰지 않는 앱**: 할 일이 없다. 런타임 SDK가 자동으로 바뀌어도 기존 표면은 그대로다.
- **SMS로 전환하는 앱**: `features_used ∋ account`인 파일 가운데 로그인·가입 화면만 위 규칙에 맞춰 고친다. 이 변경은 Tier 2다.
