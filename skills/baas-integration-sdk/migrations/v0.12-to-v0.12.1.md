# v0.12 → v0.12.1 마이그레이션

**문서 정정 + SDK 타입 보강 전용. 런타임 동작·엔드포인트·시그니처는 하나도 바뀌지 않았다(Tier 0).**
`changed_features` 가 비어 있으므로 배포된 어떤 앱도 재생성·수정 대상이 아니다.
(검증: 이 변경 전후 번들의 엔드포인트 36개·문자열 리터럴 119개가 전부 동일 — 타입/주석은 빌드 시 소거된다.)

## 왜 올렸나 — 실측 결함 3건의 원인이 전부 이 문서였다

생성 에이전트가 만든 앱이 `tsc` · `eslint` · `build` 를 **전부 통과하고 배포본에서만** 크래시한 사례가
연속 세대에서 반복됐다. 원인을 배포 SDK 번들 디컴파일 + 실제 REST 응답 대조로 확정한 결과,
**SDK 동작이 아니라 이 스킬 문서가 실제 계약과 달랐다.**

| 실측 결함 | 문서의 잘못 |
|---|---|
| 클래스 상세 전체 크래시 (`target.price` 접근) | `fetchTarget()` 반환 shape 을 **아예 문서화하지 않음**("운영설정·폼·결제정책"이라고만 서술). 실제로는 `reservation_settings.payment_policy.amount` 로 중첩 |
| `/store` 진입 즉시 크래시 (`products.map`) | `fetchProducts` 를 "SDK가 정규화" 로 서술 → 반환값이 배열인 줄 알게 함. 실제 반환은 `{ items }` 봉투이고 **배열은 훅 state `products` 에만** 담긴다 |
| 예약 슬롯 빈 화면 + 시각 오류 | `fetchSlots()` 가 `{ target_id, date, slots }` 봉투를 준다는 것과, 슬롯의 시각 필드명이 **`slot`**(요청 파라미터 `reserved_at` 과 다름)이라는 것이 미문서화 |
| (이전 세대) 실패가 성공처럼 보임 — `try/catch` 13곳 무용 | 전역 규약이 "실패 시 `BaasError` throw" 라고 **반대로** 서술. 실제 훅 액션은 `run()` 래퍼가 catch 해 **`null` 반환 + `error` state** |
| (이전 세대) 본인 글 판정 실패 | 게시판 작성자 식별 필드가 `author_id` 이고 **목록 응답엔 없다(상세에만)** 는 사실 미문서화 |

## 무엇을 고쳤나

### `reference/sdk-surface.md`
- **"⚠️ 먼저 읽을 것 — 훅 계약" 절 신설** (문서 최상단):
  - ① **실패 규약 정정** — 훅 액션은 throw 하지 않는다(`null`/`false` 반환 + `error` state).
    예외는 `beginWidgetCheckout`(throw)과 훅 없는 top-level 함수(throw).
  - ② **반환값 vs 훅 state 표** — 훅마다 규약이 셋으로 갈린다:
    (a) state=반환값 동일(`useBoard`/`useNotice`/`useFaq`/`useComments`/`useCollection`),
    (b) **state=배열 / 반환=봉투 비대칭**(`useStore.fetchProducts`, `useSurvey.fetchSurveys`),
    (c) **state 없음, 반환값만**(`useReservation.fetchTarget/fetchSlots/myBookings`,
    `useStore.fetchProduct/myOrders`).
  - ③ 훅 컨테이너 의존성 금지 · `useCollection` 컬렉션당 인스턴스 1개 (기존 규약을 상단으로 승격)
- **예약 절**: `fetchTarget()` 반환 JSON 전문 + "화면에 쓸 값 → 경로" 표,
  `fetchSlots()` 봉투 언랩 예시, `slot` vs `reserved_at` 비대칭 명시
- **스토어 절**: `fetchProducts` 는 **state 를 쓰라**는 코드 예시, `fetchProduct`/`myOrders` 는 state 없음 표시
- **게시판 절**: `author_id` 는 상세에만 존재 · "내가 쓴 글 목록"은 식별자 필터 불가라는 제약 명시

### `scaffold/wiring.md`
- **존재하지 않는 `baas.d.ts` 안내 제거.** CDN 에 그 파일이 없고(HTTP 403) `build.mjs` 도 `.d.ts` 를
  발행하지 않는다. "타입을 참조하면 tsc 가 오타를 잡는다"는 안내가 **거짓 안전감**을 줬다.
  → `window.BaasSDK` 는 타입이 없어 **모든 필드 접근이 `any`** 이고 위 결함들이 tsc 를 그냥 통과한다는
  경고로 교체.

### SDK 소스 (타입·주석만 — 런타임 무변경)
- `core/reservation.ts`: `ReservationSettings` · `ReservationSlot` · `AvailableSlotsResult` 타입 신설.
  `ReservationTarget` 이 `{id,name,is_active}` 뿐이라 실제 shape 을 전혀 기술하지 못하던 것을 보강.
  `getAvailableSlots` 는 반환 타입이 **없었다** → `AvailableSlotsResult` 지정.
- `react/moreHooks.ts`: `fetchProducts`/`fetchSurveys` 의 state/반환 비대칭에 경고 주석.

## 남은 제안 (이번 버전에서 하지 않음)

`useStore.fetchProducts` 와 `useSurvey.fetchSurveys` 의 **state/반환 비대칭 자체**는 다른 훅
(`useBoard`·`useCollection` 등 — state 와 반환이 같은 값)과 어긋나는 설계 불일치다. 통일하면 이
부류의 결함이 구조적으로 사라지지만 **반환값을 쓰는 기존 앱을 깨는 변경**이라 이번 패치에 넣지 않았다.
통일한다면 minor 이상 + 마이그레이션 노트가 필요하다.
