# v0.13 → v1.0.0 마이그레이션 (GA)

> 중간에 스킬 전용 버전 **0.13.1** 이 있었다(예약 결제 경로 선택 규칙 문서 정정 — `features.json` 과
> `sdk-surface.md` 만 변경, SDK 소스 무변경). 별도 노트 없이 이 문서가 흡수한다.

**SDK 를 1.0.0 으로 올려 프로덕션에 처음 출시한다.** 코드 변경은 없다 — 버전 문자열만 바뀐다.

**앱 조치 없음(Tier 0)** — 훅·시그니처·반환 타입·엔드포인트·화면 규약이 하나도 바뀌지 않았다.
`changed_features` 가 비어 있으므로 어떤 앱도 재생성·수정 대상이 아니다.

## 무엇이 바뀌었나

버전 숫자 둘뿐이다.

| 파일 | 이전 | 이후 |
|---|---|---|
| `sdk/package.json` (SDK 번들) | 0.13.0 | **1.0.0** |
| `features.json` (스킬) | 0.13.1 | **1.0.0** |

`sdk/src/` 는 무변경이다. 번들 내용은 빌드 시 주입되는 `SDK_VERSION` 문자열만 다르다.

## 왜 1.0.0 인가

### ① 채널 이름과 버전이 어긋나 있었다

`sdk/README.md` 의 전파 모델은 이렇게 규정한다:

> **메이저 승격**(v1→v2, 호환 깨짐)만 새 별칭. 마이너/패치는 `v1` 갱신으로 자동 전파.

그런데 `v1` 채널에 0.x 를 태우고 있었다. 1.0.0 을 올려야 **채널 = 메이저 라인**이라는 계약이 성립한다.
앞으로 `v1` 채널은 1.x 최신을 가리키고, 깨는 변경은 2.0.0 + 새 채널 `v2` 로만 나간다.

### ② 버전 두 축이 어긋나 있었다

`eacbcb5`(v0.13.1)가 `features.json` 과 문서만 바꾸고 `sdk/` 를 안 건드려서, `sdk-cd.yml` 의
`paths: sdk/**` 필터에 걸리지 않았다. 그 결과 SDK 번들은 0.13.0, 스킬은 0.13.1 로 갈라져 있었다.
1.0.0 에서 두 축을 일치시킨다.

### ③ 실제 출시 시점이다

지금까지 `v1` 채널은 0.3.0(2026-07-09)에 멈춰 있었고 **운영에 SDK 가 제공된 적이 없다.**
그 사이 `next` 채널에서 0.13.x 까지 발전했다 — 기능 그룹이 7개에서 10개로 늘었다
(`collection`·`payment`·`storage` 신설). 이번이 그 표면의 첫 프로덕션 공개다.

## 1.0.0 이 약속하는 것

- **표면 안정화** — 1.x 동안 breaking 변경 없음. 깨는 변경은 2.0.0 + 새 채널 `v2` 로만.
- **채널 = 메이저 라인** — 마이너·패치는 `v1` 채널 갱신으로 자동 전파(앱 재생성 0).
- **deprecated 별칭 유지** — `listPublicRecords`·`getPublicRecord`·`fetchPublicRecords`(컬렉션 경로
  통합의 잔존 별칭)는 1.x 동안 유지하고 **2.0 에서 제거**한다. 순수 별칭이라 유지비가 없고,
  `next` 채널로 생성된 앱들이 이미 쓰고 있을 수 있다.

## 0.3.0(구 v1 채널) 대비 무엇이 들어오나

승격으로 `v1` 을 소비하는 쪽에서 보면 아래가 신규다. **다만 0.3.0 을 실제로 쓰던 프로덕션 앱이
없으므로 마이그레이션 대상은 없다** — 0.3.0 → 1.0.0 구간의 breaking(`getStoreTerms` 제거,
`fetchProducts`/`fetchSurveys` 반환 변경 등)은 소비자가 없어 실효가 없다.

| 기능 그룹 | 내용 |
|---|---|
| `collection` (신규) | 동적 컬렉션 레코드 CRUD — `useCollection`, 필터 DSL, 접근 정책 기반 인가 |
| `payment` (신규) | `usePayment` — 구매약관 조회 등 결제 공통 |
| `storage` (신규) | `useFileUpload`/`uploadFile` — presign 업로드 |
| `store`·`reservation` | 결제위젯(인라인) 단일 방식으로 전환 |

## 적용 절차

- **앱**: 조치 없음. `baas-manifest.json` 의 `skill_version` 은 빌드 시 자동 갱신된다.
- **배포**: `stage` 머지 → `next` 채널 + 불변 `/1.0.0/` 배포 → 검증 → `main` 머지 → `v1` 승격
  (재빌드 없이 `/1.0.0/` 복사).
- **롤백**: `SDK_VERSION=0.3.0 SDK_CHANNEL=v1 npm run promote` (0.3.0 불변 경로 보존됨).

## 참고: 백엔드 전제

동적 컬렉션은 서버의 컬렉션 정책 게이트가 배포된 환경에서만 동작한다. SDK 1.0.0 출시와 별개로
프로덕션 백엔드 준비가 끝나야 `collection` 기능이 실제로 동작한다 — 신규 표면이라 기존 앱에는
영향이 없고, 백엔드가 준비되는 시점부터 앱이 쓰기 시작하면 된다.
