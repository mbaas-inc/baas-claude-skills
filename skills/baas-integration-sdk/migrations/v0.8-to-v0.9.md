# v0.8 → v0.9 마이그레이션

**⚠️ BREAKING — 리다이렉트 결제 경로가 제거됐다.** `useStore().checkout` / `useReservation().checkout` 이 없어지고 **결제위젯(인라인) 단일 방식**으로 통일됐다.

> 이 노트는 사후 작성됐다. 당시 버전을 올릴 때 마이그레이션 문서를 남기지 않아 0.7→0.9 구간이 비어 있었고, 이력 보존을 위해 채웠다.

## 무엇이 제거됐나

| 제거 | 대체 |
|---|---|
| `useStore().checkout()` | `useStore().beginWidgetCheckout()` |
| `useReservation().checkout()` | `useReservation().beginWidgetCheckout()` |
| `startStoreCheckout` / `StoreCheckoutOptions` (core) | `beginStoreWidgetCheckout` |
| `startReservationCheckout` (core) | `beginReservationWidgetCheckout` |
| `requestCardPayment` / `payment` 타입 (core, 내부) | `renderPaymentWidget` |

체크아웃 컨텍스트 헬퍼(`getStoreCheckoutContext`·`clearStoreCheckoutContext` 및 예약 대응물)는 **유지**된다.

## 왜

결제 중 앱 화면(뒤로가기)이 유지되어야 한다는 UX 요구가 확정됐다. 두 방식을 병행하면 앱마다 키 접두어(`ck_`/`gck_`)로 분기해야 해서, 그 분기 자체를 없앴다.

당시 리다이렉트 `checkout()` 을 실제로 쓰던 배포 앱은 buvamo 하나였고 이미 위젯으로 전환한 뒤라 안전하다고 판단했다.

## 앱 조치 (Tier 2)

`checkout()` 호출을 `beginWidgetCheckout()` 으로 바꾸고, **위젯이 렌더될 컨테이너 2개(결제수단·약관)** 를 화면에 두어야 한다. 호출 형태가 달라 기계적 치환이 되지 않는다(codemod 없음).

```tsx
// before — 리다이렉트
await checkout({ productId, ... });

// after — 인라인 위젯
const handle = await beginWidgetCheckout({ productId, ..., 
  paymentMethodsSelector: "#payment-methods", agreementSelector: "#agreement" });
// 결제 버튼 클릭 핸들러에서 동기로 호출
handle.requestPayment();
```

⚠️ **`handle.requestPayment` 는 클릭 핸들러 안에서 동기로 호출한다** — 앞에 `await` 를 두면 사용자 제스처가 끊겨 일부 카드사 결제창이 뜨지 않는다. 자세한 규약은 `reference/sdk-surface.md` 의 결제 공통 절 참조.

## 전제

- 프로젝트 토스 키가 **결제위젯 키(`gck_`)** 여야 한다. 개별연동 키(`ck_`)는 위젯을 지원하지 않으므로 키 교체가 선행돼야 한다.

## 후속 (v0.9.1)

`useStore().fetchTerms`(구매약관 조회)가 추가되고, 결제 필수 표시 규약(구매약관 동의 게이트 + 통신판매중개업 고지 푸터)이 `reference/sdk-surface.md` 로 이식됐다. `fetchTerms` 는 v0.10 에서 `usePayment().fetchTerms` 로 이동한다 — `v0.9-to-v0.10.md` 참조.
