# v0.11 → v0.12 마이그레이션

두 가지가 들어갔다: **① 컬렉션 읽기 경로 통합**(transport), **② 스킬 ↔ CLI 경계 정리**(문서).

**앱 코드 영향 없음(Tier 0)** — SDK 훅·시그니처·반환 타입·화면 규약은 하나도 바뀌지 않았다.
`changed_features` 가 비어 있으므로 어떤 앱도 재생성·수정 대상이 아니다.

## ① 컬렉션 읽기 경로 통합 (transport)

비로그인 읽기가 쓰던 `/public/collections/{projectId}/...` 전용 경로를 없애고 `/collections/...`
한 벌로 합쳤다. 서버가 인증 게이트를 미들웨어에서 **컬렉션 정책(`settings.access`)** 으로 옮겨,
`/collections` 가 비로그인에도 열리고 허용 여부는 정책이 판정하기 때문이다.

- **앱 조치 없음** — `listPublicRecords`·`getPublicRecord`·`fetchPublicRecords` 는 별칭으로 남아
  기존 호출이 그대로 동작한다. SDK 가 경로 변경을 흡수한다(Tier 0 의 정의).
- **신규 코드** 는 `fetchRecords`/`fetchRecord` 를 쓴다 — 로그인 여부로 함수를 고를 필요가 없다.
- **동작 차이(주의)**: 로그인 상태에서 공개 별칭을 부르면 이제 회원 스코프로 판정된다.
  `read: [public, owner]` 같은 혼합 정책에서 공개분만 보려면 `filter` 로 명시해야 한다.

**채널·백엔드 전제**: 이 통합은 서버의 정책 게이트가 배포된 환경에서만 의미가 있다.
`next` 채널(dev)은 반영 완료. `v1`(prod) 승격은 prod 백엔드에 정책 게이트가 올라간 뒤다.

## ② 스킬 ↔ CLI 경계 정리 (문서)

이 스킬에서 **`baas` CLI 의 명령·플래그 문법을 제거**했다. SDK 표면과
"무엇을 프로비저닝해야 하는가"(리소스 종류·스키마·접근 정책 의미론)는 그대로 남고, **어떻게 실행하는가**는
설치된 CLI 의 `--help` 가 권위가 된다.

### 무엇이 바뀌었나 (문서 경계)
- **제거**: `baas collection create/field add`, `baas board create --type … --ensure`,
  `--access-json '{...}'` JSON 예시, `baas collection get <name>` 등 **명령·플래그 표기**
- **유지**: 접근 정책 모델(`create/read/update/delete` × `public|member|owner|ref_owner:<field>`),
  관계 설계 패턴(자식 컬렉션 / 트리 anchor+parent / N:M 정션), 필드 타입·필터 DSL·1-hop 제약
  → 이건 **무엇을 프로비저닝할지·어떤 데이터를 누가 읽는지** 결정하는 의미론이라 스킬 소관이다
- **신설**: `SKILL.md` 에 "범위 경계" 절 — 정의하는 것 / 정의하지 않는 것을 명시

## 왜 (② 문서 경계)
1. **버전 라인 독립** — 스킬과 `baas` CLI 는 릴리스가 따로다(스킬 0.12.0 / CLI 0.6.x). 스킬에 플래그를
   박아두면 CLI 가 바뀔 때 아무도 잡지 못해 조용히 낡는다. 실제로 CLI help 에 없는 명령이 안내되던
   사례가 있었다(baas-cli#11).
2. **소유권 역전 해소** — 역할 분리 환경에서 CLI 실행은 **프로비저닝 담당(backend_operator)** 소유이고,
   이 스킬을 읽는 UI/연동 구현자(feature_engineer)는 **CLI 변경 명령이 금지**돼 있다. 쓸 수 없는 쪽에게
   문법을 가르치던 상태였다.

## 적용 절차
- **앱**: 조치 없음(①② 모두). 런타임 SDK·매니페스트 `features_used` 변화 없음.
  경로 통합은 채널 갱신으로 자동 반영된다(재생성·재빌드 0).
  (`baas-manifest.json` 의 `skill_version` 은 빌드 시 자동 갱신된다.)
- **에이전트 환경**: 프로비저닝 담당(backend_operator)이 **접근 정책·관계 패턴 의미론**을 알아야 하므로,
  이 스킬을 UI/연동 담당뿐 아니라 **프로비저닝 담당에게도 로드**하는 것이 맞다. CLI 문법은 계속
  `baas <group> <action> --help` 로 확인한다.
